C++20 / header-only library

The project targets C++20 (CMAKE_CXX_STANDARD 20). Almost all logic lives in headers included by the single translation unit source/main.cpp. That style (header-only) keeps the educational cipher easy to browse: open a .hpp and you see the full implementation—no separate .cpp library objects to link.

Where used CMakeLists.txt · include/mini_aes/*.hpp · source/main.cpp 
set(CMAKE_CXX_STANDARD 20)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
add_executable(mini_aes source/main.cpp)
target_include_directories(mini_aes PRIVATE include)

Namespaces & nested detail

A namespace groups related names and avoids collisions with other libraries. Nested detail (or mini_aes::detail) is a common convention for implementation helpers that callers should not treat as public API— for example the GF multiply table builder or MixColumn helpers.

Where used include/mini_aes/gf16.hpp · include/mini_aes/transforms.hpp 
namespace mini_aes::detail {
inline constexpr auto kGf16MulTable = build_gf16_mul_table();
} // namespace mini_aes::detail

namespace mini_aes {
class Nibble { /* ... */ };
}

#pragma once

An include guard: the preprocessor includes the header at most once per translation unit. Equivalent in spirit to classic #ifndef / #define guards, with less boilerplate. Every Mini-AES header starts with it.

Where used All files under include/mini_aes/ 
#pragma once

#include <array>
#include <cstdint>

constexpr / compile-time tables

constexpr means a function or variable can be evaluated at compile time. Here, the full 16×16 GF(2⁴) multiplication table and the inverse S-box are built when the program is compiled, so runtime only does O(1) lookups— no bit-serial polynomial multiply in the hot path.

Where used include/mini_aes/gf16.hpp (build_gf16_mul_table) · include/mini_aes/sbox.hpp (build_inv_sbox) 
inline constexpr std::array<std::array<std::uint8_t, 16>, 16>
build_gf16_mul_table() noexcept {
    std::array<std::array<std::uint8_t, 16>, 16> table{};
    constexpr std::uint8_t modulus = 0x13; // x^4 + x + 1
    // ... fill table[a][b] ...
    return table;
}

inline constexpr auto kGf16MulTable = build_gf16_mul_table();

inline variables & functions

In headers, inline on a function (or C++17+ inline variable) allows the same definition to appear in multiple translation units without violating the One Definition Rule. Essential for a header-only library: tables like kSBox and free transforms like nibble_sub are defined in headers safely.

Where used include/mini_aes/sbox.hpp · include/mini_aes/transforms.hpp · gf16.hpp tables 
inline constexpr std::array<std::uint8_t, 16> kSBox = { /* ... */ };

[[nodiscard]] inline State nibble_sub(const State& input,
                                      bool inverse = false) noexcept;

Strong types / encapsulation

Wrapping a raw uint8_t in class Nibble (and a 16-bit block in State, the API in Cipher) makes invalid states harder: masking to 4 bits happens in the constructor, and field operations are methods/ operators on the type—not ad-hoc bit fiddling at every call site.

Where used include/mini_aes/gf16.hpp (Nibble) · state.hpp · cipher.hpp · key_schedule.hpp 
class Nibble {
public:
    static constexpr std::uint8_t kMask = 0x0F;
    explicit constexpr Nibble(std::uint8_t value) noexcept
        : value_(value & kMask) {}
    [[nodiscard]] constexpr std::uint8_t value() const noexcept { return value_; }
private:
    std::uint8_t value_ = 0;
};

explicit constructors

explicit blocks implicit conversions. Without it, Nibble n = 5; or passing an integer where a Cipher is expected could happen silently. Callers must write Nibble{5} / Cipher(key) on purpose.

Where used Nibble, State, KeySchedule, Cipher constructors 
explicit Cipher(std::uint16_t secret_key) : schedule_(secret_key) {}
explicit KeySchedule(std::uint16_t secret_key);

Operator overloading & friend

Overloading + and * lets GF(2⁴) arithmetic read like math: addition is XOR, multiplication is table lookup. Declaring binary operators as friend (or free functions) keeps left/right operands symmetric and allows access to private value_ when needed.

Where used include/mini_aes/gf16.hpp 
[[nodiscard]] friend constexpr Nibble operator+(Nibble lhs, Nibble rhs) noexcept {
    return Nibble{static_cast<std::uint8_t>(lhs.value_ ^ rhs.value_)};
}

[[nodiscard]] friend constexpr Nibble operator*(Nibble lhs, Nibble rhs) noexcept {
    return Nibble{detail::kGf16MulTable[lhs.value_][rhs.value_]};
}

[[nodiscard]] & noexcept

[[nodiscard]] warns if a return value is ignored—important for pure transforms that return a new State. noexcept promises the function will not throw, which helps optimizers and documents intent for small value-type operations that only do arithmetic and table lookups.

Where used Widespread across gf16.hpp, sbox.hpp, state.hpp, transforms.hpp, cipher.hpp 
[[nodiscard]] inline State shift_row(const State& input) noexcept {
    const auto& n = input.nibbles();
    return State::from_nibbles(n[0], n[3], n[2], n[1]);
}

static factory methods

Named static constructors (from_uint16, from_nibbles) document how a value is built better than overloaded constructors alone, and keep packing/unpacking logic next to the type that owns the representation.

Where used include/mini_aes/state.hpp 
[[nodiscard]] static constexpr State from_uint16(std::uint16_t block) noexcept {
    return State{{Nibble{static_cast<std::uint8_t>(block >> 12)},
                  Nibble{static_cast<std::uint8_t>((block >> 8) & 0x0F)},
                  Nibble{static_cast<std::uint8_t>((block >> 4) & 0x0F)},
                  Nibble{static_cast<std::uint8_t>(block & 0x0F)}}};
}

Const / non-const overloads

Providing both const and non-const accessors lets read-only code use const State& safely while mutating code (e.g. MixColumn writing columns) gets a reference. The compiler picks the overload from the object’s constness.

Where used include/mini_aes/state.hpp (column_top, column_bottom, nibbles) 
[[nodiscard]] constexpr Nibble column_top(std::size_t column) const noexcept;
[[nodiscard]] constexpr Nibble& column_top(std::size_t column) noexcept;

Free-function API vs class API

Round transforms are free functions (nibble_sub, shift_row, …): they are pure mappings on State with no long-lived identity. Cipher / KeySchedule are classes because they own configuration (the expanded keys) and expose a higher-level operation. Mixing both styles keeps low-level steps composable and the public encrypt/decrypt surface small.

Where used include/mini_aes/transforms.hpp · include/mini_aes/cipher.hpp 
// Free transform
[[nodiscard]] inline State mix_column(const State& input) noexcept;

// Class facade
class Cipher {
    [[nodiscard]] std::uint16_t encrypt(std::uint16_t plaintext,
                                        TraceCallback trace = {}) const;
};

Value semantics (return new state)

Transforms take const State& and return a new State instead of mutating in place. That makes each step easy to reason about and to print in a trace: the previous matrix is unchanged after the call. For a 4-nibble state the copy cost is negligible.

Where used include/mini_aes/transforms.hpp · Cipher::encrypt / decrypt pipelines 
state = nibble_sub(state);
state = shift_row(state);
state = mix_column(state);
state = add_round_key(state, schedule_.round_key(1));

std::array

Fixed-size, stack-friendly container with value semantics and constexpr support. Preferred here over C arrays or std::vector because nibble counts, S-box size, and round-key count are known at compile time.

Where used GF table, S-boxes, State nibbles, KeySchedule::round_keys_ 
std::array<State, kRoundKeyCount> round_keys_{};
inline constexpr std::array<std::uint8_t, 16> kSBox = { /* 16 entries */ };

std::string_view

A non-owning view of a character sequence. Trace labels are string literals or temporary views—no need to allocate a std::string for every step. Lifetime: the view must not outlive the characters it points to (fine for literals).

Where used include/mini_aes/state.hpp · include/mini_aes/cipher.hpp · source/main.cpp 
void print_trace(std::string_view label, std::ostream& out = std::cout) const {
    out << label << '\n';
    print(out);
}

std::function callbacks

Type-erased callable wrapper. TraceCallback can bind a free function, lambda, or functor. Default-constructed {} is empty; the cipher checks if (trace) before calling—so tracing is optional with zero API surface for callers who skip it.

Where used include/mini_aes/cipher.hpp · source/main.cpp 
using TraceCallback = std::function<void(std::string_view, const State&)>;

static void trace_step(const TraceCallback& trace,
                       std::string_view label,
                       const State& state) {
    if (trace) {
        trace(label, state);
    }
}

Type aliases (using)

using TraceCallback = ... gives a readable name to a long template type and keeps the public typedef next to the class that owns the policy.

Where used include/mini_aes/cipher.hpp 
class Cipher {
public:
    using TraceCallback = std::function<void(std::string_view label,
                                             const State& state)>;
};

Exceptions for API bounds

KeySchedule::round_key throws std::out_of_range if the round index is not 0..2. That turns a programming mistake into a clear failure instead of undefined behavior from an unchecked array index. The encrypt/decrypt paths only use valid indices, so the throw is a guard for external callers.

Where used include/mini_aes/key_schedule.hpp 
[[nodiscard]] const State& round_key(std::size_t round) const {
    if (round >= kRoundKeyCount) {
        throw std::out_of_range("Mini-AES supports round keys 0..2 only");
    }
    return round_keys_[round];
}

Anonymous namespace

namespace { ... } in a .cpp file gives internal linkage: helpers are invisible to other translation units (like static at file scope). Used in main.cpp for print/trace helpers that are not part of the library API.

Where used source/main.cpp 
namespace {

void print_header() { /* ... */ }
void trace_state(std::string_view label, const mini_aes::State& state) {
    state.print_trace(label);
}

} // namespace

Umbrella include

mini_aes.hpp re-includes the public headers so a client can write a single #include "mini_aes/mini_aes.hpp". The demo includes cipher.hpp directly instead—either style is fine; the umbrella is for convenience when you want the whole library.

Where used include/mini_aes/mini_aes.hpp 
#pragma once
#include "cipher.hpp"
#include "gf16.hpp"
#include "key_schedule.hpp"
#include "sbox.hpp"
#include "state.hpp"
#include "transforms.hpp"

Project design decisions

Beyond language features, a few intentional choices shape the code:

  • Compile-time GF table — replaces a long bit-serial multiply loop with kGf16MulTable[a][b]; easier to teach field arithmetic once, then trust O(1) ops in MixColumn.
  • Self-inverse π and θ — ShiftRow and MixColumn are their own inverses on this 2×2 layout / matrix, so decryption reuses the same functions (only NibbleSub needs inv_sbox).
  • Optional trace callback — teaching and debugging without #ifdef or separate “verbose” cipher types; empty std::function means no overhead beyond one null check per step.
  • Separation of concerns — field, S-box, state, transforms, key schedule, and cipher each get a header so the process in PLAN.md maps 1:1 to files.
Where used Cross-cutting · see also ../PLAN.md 
// Final round omits MixColumn (AES-like structure)
state = nibble_sub(state);
state = shift_row(state);
state = add_round_key(state, schedule_.round_key(2));
